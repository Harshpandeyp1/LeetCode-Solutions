You are keeping the scores for a baseball game with strange rules. At the beginning of the game, you start with an empty record.

You are given a list of strings operations, where operations[i] is the ith operation you must apply to the record and is one of the following:

An integer x.
Record a new score of x.
'+'.
Record a new score that is the sum of the previous two scores.
'D'.
Record a new score that is the double of the previous score.
'C'.
Invalidate the previous score, removing it from the record.
Return the sum of all the scores on the record after applying all the operations.

The test cases are generated such that the answer and all intermediate calculations fit in a 32-bit integer and that all operations are valid.



import java.util.Stack;

class Solution {
    public int calPoints(String[] operations) {
        // Stack to keep track of valid scores in order
        Stack<Integer> stack = new Stack<>();
        
        for (String operation : operations) {
            
            if (operation.equals("+")) {
                // "+" : new score = sum of previous two scores
                int a = stack.pop();   // last score
                int b = stack.pop();   // second-to-last score
                stack.push(b);         // restore second-to-last score
                stack.push(a);         // restore last score
                stack.push(a + b);     // push new score (sum of both)
                continue;
            }
            
            if (operation.equals("D")) {
                // "D" : new score = double the previous score
                stack.push(stack.peek() * 2);
                continue;
            }
            
            if (operation.equals("C")) {
                // "C" : invalidates and removes the previous score
                stack.pop();
                continue;
            }
            
            // Otherwise, operation is a number string (e.g. "5", "-3")
            // Push it directly onto the stack as a new score
            stack.push(Integer.parseInt(operation));
        }
        
        // Sum up all remaining valid scores in the stack
        int total = 0;
        while (!stack.isEmpty()) total += stack.pop();
        
        return total;
    }
}

1. Using ArrayDeque instead of Stack (recommended — faster, no synchronization overhead)
java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int calPoints(String[] operations) {
        Deque<Integer> st = new ArrayDeque<>();
        
        for (String op : operations) {
            switch (op) {
                case "C":
                    st.pop();
                    break;
                case "D":
                    st.push(2 * st.peek());
                    break;
                case "+":
                    int top = st.pop();
                    int second = st.peek();
                    st.push(top);
                    st.push(top + second);
                    break;
                default:
                    st.push(Integer.parseInt(op));
            }
        }
        
        int sum = 0;
        for (int score : st) sum += score;
        return sum;
    }
}
Notes on this version:

ArrayDeque is generally preferred over Stack in modern Java since Stack extends Vector and is synchronized (slower, legacy class).
Switching on the whole String (op) instead of op.toCharArray()[0] is cleaner and avoids char-based edge cases entirely.
Iterating the deque directly to sum avoids the pop-loop.
2. Using an ArrayList as a stack (array-index based, avoids Stack/Deque entirely)
java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public int calPoints(String[] operations) {
        List<Integer> st = new ArrayList<>();
        
        for (String op : operations) {
            int n = st.size();
            switch (op) {
                case "C":
                    st.remove(n - 1);
                    break;
                case "D":
                    st.add(2 * st.get(n - 1));
                    break;
                case "+":
                    st.add(st.get(n - 1) + st.get(n - 2));
                    break;
                default:
                    st.add(Integer.parseInt(op));
            }
        }
        
        int sum = 0;
        for (int score : st) sum += score;
        return sum;
    }
}
This is nice because "+" doesn't require popping and re-pushing — you just peek at the last two elements by index, which mirrors the problem statement more directly ("the sum of the previous two scores").

3. Using a plain array (fastest, O(1) space overhead avoided)
java
class Solution {
    public int calPoints(String[] operations) {
        int[] st = new int[operations.length];
        int i = 0; // pointer to top of stack
        
        for (String op : operations) {
            switch (op) {
                case "C":
                    i--;
                    break;
                case "D":
                    st[i] = 2 * st[i - 1];
                    i++;
                    break;
                case "+":
                    st[i] = st[i - 1] + st[i - 2];
                    i++;
                    break;
                default:
                    st[i] = Integer.parseInt(op);
                    i++;
            }
        }
        
        int sum = 0;
        for (int j = 0; j < i; j++) sum += st[j];
        return sum;
    }
}
This avoids object overhead (Integer boxing/unboxing) and any collection library entirely — just a fixed-size array sized to operations.length (the max possible stack size), with a manual pointer i tracking the top. This is typically the fastest in practice for LeetCode-style constraints.

Which to pick: for readability, go with option 1 (ArrayDeque) or option 2 (ArrayList). For raw performance on large inputs, option 3 (plain array) wins since it avoids autoboxing and dynamic resizing.

Approach
Problem restated: You're given a sequence of operations representing a baseball-style scoring record. Each operation either records a new score or modifies/cancels previous scores. You need the sum of all valid scores at the end.

Key idea — use a stack:
Since operations like "D", "+", and "C" only depend on the most recent score(s), a stack is a natural fit: it always gives you fast access to the top (most recent) elements, and lets you undo/modify recent entries in O(1) time.

Step-by-step logic:

Number (e.g. "5") → It's a fresh score. Just push it onto the stack.
"C" (cancel) → The previous score was invalid. Pop it off (remove it permanently).
"D" (double) → New score is double the previous one. Peek at the top, compute 2 * top, and push that as a new score (previous score stays in the stack).
"+" (sum) → New score is the sum of the previous two scores. Pop the top two values (a = last, b = second-to-last), push them back in their original order (since they're still valid), then push their sum a + b as the new score.
Why push b then a back for "+"?
Popping removes elements, so after popping a and b, the stack no longer has them. Since both scores remain valid, they need to be restored in their original relative order before adding the new sum on top — otherwise, a later "+" or "D" would peek the wrong value.

Final step:
Once all operations are processed, the stack holds every currently valid score. Just pop everything and sum it up.

Complexity:

Time: O(n), where n is the number of operations — each operation does O(1) work.
Space: O(n) for the stack in the worst case (all operations are numbers).
