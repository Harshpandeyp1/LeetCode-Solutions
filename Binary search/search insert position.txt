Given a sorted array of distinct integers and a target value, return the index if the target is found. If not, return the index where it would be if it were inserted in order.

You must write an algorithm with O(log n) runtime complexity.

 


class Solution {
    public int searchInsert(int[] nums, int target) {
        int n = nums.length;
        int left = 0;
        int right = n - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;

            if (target == nums[mid]) {
                return mid;
            } else if (target < nums[mid]) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        }
        return left; // insertion point
    }
}

Why left is the answer when not found
Think about what's true right when the loop exits:

Everything from 0 to left - 1 is < target
Everything from left to n - 1 is > target

That means left is precisely the index where target should be inserted to keep the array sorted — every element before it is smaller, every element from it onward is larger.
Example: nums = [1, 3, 5, 6], target = 2

left=0, right=3, mid=1 → nums[1]=3 > 2 → right = 0
left=0, right=0, mid=0 → nums[0]=1 < 2 → left = 1
Now left=1 > right=0, loop ends → return left = 1

Indeed, inserting 2 at index 1 gives [1, 2, 3, 5, 6] — correct.
